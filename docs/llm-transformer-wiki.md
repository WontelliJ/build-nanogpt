# LLM 동작 원리

## 예시

```text
사용자: 민수는 사과를 좋아해.
AI:     민수는 사과를 좋아하는군요.

사용자: 그럼 그 사람에게 뭘 사주면 좋을까?
AI:     사과를 추천해요.
```

- 두 번째 질문에는 민수도 사과도 없다. 그런데 모델은 앞 대화를 참고해서 그 사람이 민수이고 민수가 좋아하는 것이 사과라는 점을 연결해 답한다.
- 아래 단계를 차례로 거치며 이 연결이 만들어진다. 문서 속 번호, 벡터, 비율, 확률은 설명용 값이다.

<sub>LLM(Large Language Model, 대규모 언어 모델): 많은 글을 학습해서 주어진 글 다음에 올 말을 예측하는 모델<br>
Token(토큰): 모델이 글을 처리하는 단위. 단어 하나일 수도 있고 글자 몇 개나 조사 하나일 수도 있다<br>
벡터: 숫자 여러 개를 한 줄로 묶은 값. 예: [0.9, 0.8, 0.1]<br>
Transformer(트랜스포머): 2017년 발표된 신경망 구조. 현재 LLM 대부분의 기반<br>
가중치: 신경망 안에서 곱해지는 숫자들. 처음엔 무작위 값이고 학습으로 정해진다</sub>

---

## 전체 흐름

```text
Token                    문장을 조각으로 자르고 번호를 붙인다
  ↓
Embedding                번호를 의미를 담는 벡터로 바꾼다
  ↓
Position Information     몇 번째 자리인지를 벡터에 더한다
  ↓
Self-Attention           앞쪽 Token에서 필요한 정보를 가져온다
  ↓
Multi-Head Attention     여러 관점으로 동시에 가져온다
  ↓
Feed Forward Network     가져온 정보를 Token마다 가공한다
  ↓
Residual Connection      원래 정보 위에 새 정보를 더한다
  ↓
Layer Normalization      값의 크기를 일정하게 맞춘다
  ↓
Transformer Block × N    위 묶음을 여러 번 반복해 의미를 업그레이드한다
  ↓
Logits                   마지막 자리 벡터로 모든 후보 Token의 점수를 낸다
  ↓
Probability              점수를 확률로 바꾼다
  ↓
Next Token               Token 하나를 고른다
  ↓
반복                     고른 Token을 붙이고 다시 계산한다
```

- Token부터 Position Information까지는 입력을 준비하는 단계로 처음에 한 번 한다.
- Self-Attention부터 Transformer Block × N까지는 각 Token의 의미를 문맥에 맞게 업그레이드하는 단계다.
- Logits부터 반복까지는 업그레이드된 결과로 답을 한 Token씩 만드는 단계다.

---

## 1. Token

> 문장을 Token 단위로 자르고 각 Token에 사전 번호(Token ID)를 붙인다.

왜
- 문장은 경우의 수가 끝이 없어서 통째로는 다룰 수 없다. 반복해서 나오는 조각으로 자르면 정해진 개수의 조각으로 어떤 문장이든 표현할 수 있다.
- 신경망은 숫자만 계산한다. 그래서 각 조각에 번호를 붙인다.

어떻게
- 많은 글에서 자주 붙어 나오는 글자 조합을 하나의 Token으로 등록해 사전을 만든다. 자주 쓰는 좋아는 한 Token이 되고 드문 단어는 아는 조각 여러 개로 나뉜다.
- 사전 크기는 모델마다 다르며 수만~수십만 개다(GPT-2는 50,257개).

```text
입력      민수는 사과를 좋아해.
Token     [민수] [는] [사과] [를] [좋아해] [.]
Token ID  [ 12 ] [ 7] [ 31 ] [ 8] [  45  ] [2]

입력      그럼 그 사람에게 뭘 사주면 좋을까?
Token     [그럼] [그] [사람] [에게] [뭘] [사주면] [좋을까] [?] [AI 차례]
```

- 설명을 위해 단어와 조사 단위로 잘랐다. 실제 Tokenizer는 더 잘게 자르기도 한다(GPT-4o는 첫 문장을 9개로 자른다).
- 대화는 두 번의 주고받음이 하나의 긴 Token 목록으로 이어져 들어간다. 맨 끝의 [AI 차례]는 이제 AI가 답할 차례라는 표시이고 이 문서에서 마지막 자리라고 부르는 곳이다.

반영된 것
- 문장이 숫자 목록이 되어 계산할 수 있게 됐다.

남은 문제
- 번호는 사전의 칸 번호일 뿐 의미가 없다. 31과 32가 가깝다고 뜻이 비슷한 것이 아니다. 다음 단계에서 번호를 의미를 담을 수 있는 벡터로 바꾼다.

<sub>Token ID: 각 Token에 붙은 사전 번호<br>
Tokenizer(토크나이저): 문장을 Token으로 자르고 번호를 붙이는 도구<br>
BPE(Byte Pair Encoding): 자주 붙어 나오는 글자 쌍을 반복해서 합쳐 Token 사전을 만드는 방법. 대부분의 LLM이 쓴다<br>
특수 Token: 글자가 아니라 역할을 나타내는 Token. 화자 구분, 말 끝 표시 등에 쓴다</sub>

## 2. Embedding

> 번호를 숫자 여러 개로 된 벡터로 바꾼다. 비슷하게 쓰이는 Token은 비슷한 벡터를 갖는다.

왜
- 번호로는 비교할 수 없다. 사과(31)는 번호상 바나나(9137)보다 민수(12)에 가깝지만 의미와는 무관하다.
- 번호로는 섞을 수도 없다. 다음 단계들은 여러 Token의 정보를 비율대로 섞는 계산이라 벡터가 필요하다.

어떻게
- Token 수만큼 줄이 있는 표에서 번호에 해당하는 줄을 꺼낸다.
- 표의 값은 처음엔 무작위이고 학습하면서 비슷한 자리에 자주 쓰이는 Token끼리 가까워지도록 조정된다.

```text
민수    12   → [0.1, 0.2, 0.9]
사과    31   → [0.9, 0.8, 0.1]
바나나  9137 → [0.8, 0.9, 0.2]

사과·바나나 = 0.9×0.8 + 0.8×0.9 + 0.1×0.2 = 1.46   비슷함
사과·민수   = 0.9×0.1 + 0.8×0.2 + 0.1×0.9 = 0.34   다름
```

반영된 것
- Token 사이의 비슷함을 계산할 수 있다.
- 여러 Token의 정보를 섞을 수 있다. 민수 벡터 70%와 사과 벡터 30%를 더하면 두 정보가 함께 담긴 벡터가 된다.

남은 문제
- 순서를 모른다. 벡터에는 이 Token이 몇 번째인지 들어 있지 않다.
- 문맥도 모른다. 배가 고파서 사과를 먹었다의 사과와 약속에 늦어서 사과를 했다의 사과가 같은 벡터다.
- 순서는 다음 단계인 Position Information이 해결하고 문맥은 Self-Attention이 해결한다.

<sub>Embedding(임베딩): Token 번호를 벡터로 바꾸는 표<br>
차원: 벡터 하나에 든 숫자의 개수. 위 예는 3차원이고 GPT-2는 768차원<br>
내적: 두 벡터의 같은 칸끼리 곱해서 모두 더한 값. 방향이 비슷할수록 크다</sub>

## 3. Position Information

> 각 Token 벡터에 몇 번째 자리인지 나타내는 위치 벡터를 더한다.

왜
- 다음 단계인 Self-Attention은 문장을 한 단어씩 읽지 않고 모든 Token을 한꺼번에 본다. 그래서 멀리 있는 정보도 흐려지지 않지만 순서 정보가 사라진다.
- Transformer 이전의 RNN은 한 단어씩 순서대로 읽어서 순서는 알았지만 문장이 길어지면 앞 내용이 흐려졌다. Transformer는 전체를 한꺼번에 보는 방식으로 이 문제를 풀고 사라진 순서는 위치 벡터로 따로 알려 준다.

```text
사람이 사과를 먹는다.   →  [사람] [이] [사과] [를] [먹는다]
사과가 사람을 먹는다.   →  [사과] [가] [사람] [을] [먹는다]

위치 정보가 없으면 둘 다 { 사람, 사과, 먹는다, 이/가, 을/를 }
→ 이/가가 사람에 붙었는지 사과에 붙었는지 알 수 없어 두 문장을 구분하지 못한다
```

어떻게
- 자리마다 위치 벡터를 정해 두고 Token 벡터에 더한다. Token 벡터와 위치 벡터는 입력 준비 때 한 번에 더한다.

```text
0번 자리 사과 = [0.9, 0.8, 0.1] + [0.1, 0.0, 0.0] = [1.0, 0.8, 0.1]
2번 자리 사과 = [0.9, 0.8, 0.1] + [0.0, 0.0, 0.3] = [0.9, 0.8, 0.4]
```

반영된 것
- 같은 Token도 자리에 따라 다른 벡터가 된다. 이 차이를 이용해 다음 단계에서 이/가는 바로 앞 Token에 붙는다 같은 관계를 계산할 수 있다.
- 여기까지가 입력 준비다. 이후 자리는 바뀌지 않고 벡터의 내용만 업그레이드된다.

남은 문제
- 각 Token은 아직 자기 정보만 안다. 두 번째 질문의 사람은 누구를 가리키는지 모른다. 다음 단계에서 다른 Token의 정보를 가져온다.

<sub>위치 벡터: 0번 자리, 1번 자리처럼 자리마다 하나씩 정해 둔 벡터. GPT-2는 학습으로 값을 정한다. 최근 LLM 다수는 더하는 대신 벡터를 자리만큼 회전시키는 RoPE 방식을 쓴다<br>
RNN(Recurrent Neural Network, 순환 신경망): 입력을 순서대로 하나씩 처리하며 앞 내용을 다음 단계로 넘기는 신경망</sub>

## 4. Self-Attention

> 각 Token이 앞쪽 Token들 중 관련 있는 것을 찾아 그 정보를 가져와 자기 벡터에 더한다.

왜
- 사람이 누구인지, 무엇을 사 줘야 하는지는 앞 대화를 봐야 알 수 있다.

어떻게
- 각 Token 벡터에서 세 가지 벡터를 만든다.

| 벡터 | 역할 | 사람 Token의 예 |
|---|---|---|
| Query | 내가 찾는 정보 | 가리키는 대상이 누구인가 |
| Key | 내가 가진 정보의 특징. 다른 Token의 Query와 비교된다 | 민수의 Key: 사람 이름 |
| Value | 선택됐을 때 넘겨주는 정보 | 민수의 Value: 민수에 관한 정보 |

1. 각 Token이 차례로 Query가 된다.
2. Query를 앞쪽 Token들의 Key와 비교해 관련도 점수를 낸다.
3. 점수를 합이 1인 비율로 바꾼다(Softmax).
4. 비율만큼 각 Token의 Value를 가져와 자기 벡터에 더한다.

```text
Query(사람): 가리키는 대상이 누구인가

비교한 Key   민수    그     사과    좋아해
비율         0.75   0.15   0.05    0.05

사람 ← 0.75×V(민수) + 0.15×V(그) + 0.05×V(사과) + 0.05×V(좋아해)
```

- 뒤쪽 Token은 보지 않는다. 다음 Token을 맞히는 모델이라 뒤를 보면 답을 미리 보는 셈이기 때문이다.

반영된 것
- 사람 벡터에 민수 정보가 들어가 그 사람 = 민수가 연결됐다.
- 같은 사과도 앞 문맥(배가 고파서, 약속에 늦어서)에서 정보를 가져와 과일과 사죄로 다른 벡터가 된다.
- 비율은 거리가 아니라 관련도로 정해진다. 그래서 앞 대화의 민수처럼 멀리 있는 정보도 가져온다.

남은 문제
- 비율이 한 세트뿐이다. 사주면은 누구에게(민수)와 무엇을(사과)을 함께 알아야 하는데 한 세트의 비율을 나눠 쓰면 둘 다 흐릿해진다. 다음 단계에서 여러 세트를 동시에 쓴다.

<sub>Query, Key, Value(쿼리, 키, 밸류): 줄여서 Q, K, V. Token 벡터에 학습된 가중치를 곱해 만든다<br>
Softmax(소프트맥스): 점수 목록을 0~1 사이, 합이 1인 비율로 바꾸는 함수<br>
Causal Mask(인과 마스크): 뒤쪽 Token을 가려 앞쪽만 보게 하는 처리</sub>

## 5. Multi-Head Attention

> Self-Attention을 여러 갈래(Head)로 나눠 동시에 하고 결과를 합친다.

왜
- 한 Token에 필요한 관계가 여러 개다.

어떻게
- 벡터를 Head 수만큼 나눠 Head마다 따로 Q, K, V와 비율을 계산한 뒤 결과를 이어 붙인다. GPT-2는 768칸을 12개 Head가 64칸씩 나눠 쓴다.

```text
Head 1개일 때
  사주면 → 민수 0.45, 사과 0.40              둘 다 흐릿함

Head 여러 개일 때
  Head 1   사주면 → 민수 0.85                누구에게
  Head 2   사주면 → 사과 0.80                무엇을
  Head 3   사주면 → 그럼, 뭘 …               문장 구조
```

- Head가 어떤 관계를 볼지는 사람이 정하지 않고 학습으로 정해진다. 위 역할은 설명용이다.

반영된 것
- 사주면 벡터에 대상(민수)과 물건(사과) 정보가 모두 뚜렷하게 담겼다.

남은 문제
- 가져온 정보는 여러 Token의 Value를 비율대로 섞어 놓은 상태다. 이것을 좋아하는 것을 선물하면 된다 같은 판단에 쓸 특징으로 바꾸는 계산이 필요하다.

<sub>Head(헤드): Q, K, V로 비율을 계산하는 한 세트</sub>

---

## 6. Feed Forward Network

> Token마다 따로 벡터를 넓혔다가 줄이며 학습한 패턴을 적용해 가공한다. 다른 Token은 보지 않는다.

왜
- Attention은 정보를 옮겨 오기만 한다. 옮겨 온 정보에서 의미 있는 특징을 뽑아내는 계산이 따로 필요하다.

어떻게
- 768칸을 3072칸으로 넓힌다. 넓힌 칸 하나하나가 학습된 패턴이고 입력이 그 패턴과 얼마나 맞는지 점수가 된다.
- 활성화 함수(GELU)가 맞지 않는 패턴(음수)을 0 가까이 줄인다.
- 다시 768칸으로 줄이며 켜진 패턴의 결과만 더한다.

```text
사주면 벡터 (민수, 사과, 좋아함 정보가 섞임)

패턴                       점수    GELU 후
좋아하는 것 + 사 주다       2.1     2.06    켜짐
날씨 이야기                -0.8    -0.17    거의 꺼짐
장소를 묻는 질문           -1.5    -0.10    거의 꺼짐

→ 좋아하는 것을 선물로 고르는 상황이라는 특징이 더해짐
```

- 패턴(가중치)은 학습이 끝나면 고정된 일반 지식이다. 어떤 패턴이 켜지는지는 지금 대화에 따라 달라진다.

반영된 것
- 섞여 있던 정보가 답을 고르는 데 쓸 특징으로 바뀌었다.

남은 문제
- Attention과 FFN이 벡터를 새 값으로 바꿔 버리면 원래 Token 정보가 사라진다. 다음 단계에서 원래 정보를 지킨다.

<sub>FFN(Feed Forward Network, 피드포워드 신경망): Token 하나의 벡터만 받아 변환하는 작은 신경망<br>
활성화 함수: 계산 사이에 넣어 맞는 신호는 살리고 맞지 않는 신호는 줄이는 함수. GPT 계열은 GELU를 쓴다</sub>

## 7. Residual Connection

> Attention과 FFN의 결과를 원래 벡터에 덮어쓰지 않고 더한다.

왜
- 새 값으로 바꿔 버리면 원래 Token 정보가 사라지고 층을 깊게 쌓았을 때 학습도 잘 되지 않는다.

어떻게

```text
x = x + Attention(x)
x = x + FFN(x)

원래 사람 벡터     [0.2, 0.5, 0.1]
가져온 정보        [0.6, 0.1, 0.0]
더한 결과          [0.8, 0.6, 0.1]
```

반영된 것
- 원래 정보 위에 새 정보가 쌓인다. 사람 → 사람 + 민수 정보 → 사람 + 민수 정보 + 사과를 좋아함

남은 문제
- 계속 더하다 보면 값이 점점 커져 계산이 불안정해질 수 있다. 다음 단계에서 값의 크기를 맞춘다.

<sub>Residual Connection(잔차 연결): 계산 결과를 원래 입력에 더해 주는 연결</sub>

---

## 8. Layer Normalization

> Attention과 FFN에 넣기 직전에 벡터 값의 평균과 크기를 일정하게 맞춘다.

왜
- 값이 지나치게 커지거나 작아지면 계산과 학습이 불안정해진다.

어떻게
- 벡터마다 평균을 0, 퍼진 정도를 1로 맞춘다.

```text
[10.0, 0.1, -8.0]  →  [1.26, -0.08, -1.18]
```

반영된 것
- 층을 깊게 쌓아도 각 계산이 비슷한 크기의 값을 받는다.

남은 문제
- 여기까지 한 번으로는 직접 연결된 정보만 옮길 수 있다. 다음 단계에서 이 묶음을 여러 번 반복한다.

<sub>Layer Normalization(층 정규화, LayerNorm): 벡터 값의 평균과 크기를 일정하게 맞추는 계산. 최근 모델은 크기만 맞추는 RMSNorm을 많이 쓴다</sub>

---

## 9. Transformer Block × N

> Self-Attention부터 Layer Normalization까지를 묶은 Block을 여러 번 반복한다.

```text
Block 하나
x → LayerNorm → Multi-Head Attention → 더하기(Residual)
  → LayerNorm → FFN                  → 더하기(Residual) → 다음 Block
```

왜
- 한 번의 Attention은 직접 연결된 정보만 가져온다. 사주면이 사람을 볼 때 사람에 아직 민수 정보가 없을 수 있다.

어떻게
- 같은 구조의 Block을 N번 지난다. GPT-2는 12번, 현재 대형 LLM은 수십~100여 번이다. Block마다 가중치는 따로 있다.

```text
Block 1     사람        ← 민수 정보               그 사람 = 민수
Block 2     사주면      ← 사람(민수), 사과 정보     민수에게 사과
Block 3~    마지막 자리 ← 위 결과들                 답은 사과 쪽
```

| 지난 Block 수 | 마지막 자리에서 본 다음 Token 후보 |
|---|---|
| 0 (입력 준비 직후) | 네, 글쎄요 … (사과 0.1%) |
| 1 | 꽃, 선물 … (사과 2%) |
| 6 | 사과 45%, 과일 20% |
| 12 | 사과 95% |

반영된 것
- 같은 자리의 벡터가 Block마다 업그레이드되며 정보가 사과 → 민수 → 그 사람 → 마지막 자리로 전달된다.

남은 문제
- 벡터는 사람이 읽을 수 없다. 다음 단계에서 Token 후보의 점수로 바꾼다.

<sub>Transformer Block(트랜스포머 블록): Attention, FFN, Residual, LayerNorm을 묶은 반복 단위. Layer(층)라고도 한다</sub>

---

## 10. Logits

> 마지막 자리의 벡터를 사전 속 모든 Token의 점수로 바꾼다.

왜
- 결국 사전에서 Token 하나를 골라야 한다.
- 마지막 자리만 쓰는 이유는 앞쪽만 보는 규칙 때문에 이 자리가 앞 내용을 모두 받은 유일한 자리이기 때문이다.

어떻게
- 마지막 자리 벡터에 출력층을 곱해 사전 크기만큼의 점수를 만든다(GPT-2는 50,257개).

```text
사과    8.4
바나나  5.1
포도    4.0
꽃      3.2
…
```

남은 문제
- 점수만으로는 각 후보가 얼마나 그럴듯한지 비교하기 어렵다. 다음 단계에서 확률로 바꾼다.

<sub>Logits(로짓): 확률로 바꾸기 전의 원점수</sub>

---

## 11. Probability

> Softmax로 점수를 합이 100%인 확률로 바꾼다.

```text
사과 95%   바나나 3.5%   포도 1.2%   꽃 0.5%     (위 4개만으로 계산한 예)
```

- Temperature로 확률의 쏠림을 조절할 수 있다. 점수를 Temperature로 나눈 뒤 확률로 바꾼다.

```text
Temperature 1.0   사과 95%   바나나 3.5%   포도 1.2%   꽃 0.5%
Temperature 2.0   사과 73%   바나나 14%    포도 8%     꽃 5%
```

반영된 것
- 후보마다 다음에 올 가능성이 숫자로 정리됐다.

<sub>Temperature(온도): 높을수록 확률이 고르게 퍼져 다양한 답이 나오고 낮을수록 1등 후보에 쏠린다</sub>

---

## 12. Next Token

> 확률을 보고 Token 하나를 고른다.

- 가장 높은 것을 고르면 늘 같은 답이 나온다.
- 확률대로 뽑으면 95% 확률로 사과, 3.5% 확률로 바나나가 나온다. 같은 질문에도 답이 달라질 수 있는 이유다.
- 상위 몇 개 후보 안에서만 뽑기도 한다(Top-k).

```text
그럼 그 사람에게 뭘 사주면 좋을까?
                    ↓
                  사과
```

---

## 13. 반복

> 고른 Token을 맨 끝에 붙이고 다음 Token을 다시 계산한다.

이제 사과가 포함된 문맥으로 다시 다음 Token을 계산한다.

```text
... 뭘 사주면 좋을까? 사과
                    ↓
                    를
                    ↓
                 추천해요
```

- 새로 붙은 사과도 Embedding과 다음 자리의 위치 벡터를 받고 Block들을 지나 다음 Token(를)을 고른다.
- 말이 끝났다는 표시 Token이 나오면 멈춘다.
- 실제 LLM은 앞 Token들의 Key, Value를 저장해 두고(KV Cache) 새로 붙은 Token만 계산한다.

<sub>KV Cache(키-값 캐시): 앞 Token들의 Key, Value를 저장해 두는 공간</sub>

## 정리

| 단계 | 한 일 | 예시에서 반영된 것 |
|---|---|---|
| Token | 문장을 자르고 번호를 붙임 | 사과 → 31 |
| Embedding | 번호를 벡터로 | 사과와 바나나가 비슷한 벡터 |
| Position Information | 자리 벡터를 더함 | 사람이 사과를 / 사과가 사람을 구분 |
| Self-Attention | 앞쪽 Token에서 정보를 가져옴 | 그 사람 = 민수 |
| Multi-Head Attention | 여러 관점으로 동시에 가져옴 | 사주면 → 누구에게(민수), 무엇을(사과) |
| Feed Forward Network | 가져온 정보를 Token마다 가공 | 좋아하는 것을 선물하는 상황 |
| Residual Connection | 원래 정보에 새 정보를 더함 | 사람 + 민수 정보 + … |
| Layer Normalization | 값의 크기를 맞춤 | 깊게 쌓아도 계산이 안정됨 |
| Transformer Block × N | 위 묶음을 반복 | 사과 → 민수 → 그 사람 → 마지막 자리 |
| Logits | 모든 후보의 점수 | 사과 8.4 |
| Probability | 점수를 확률로 | 사과 95% |
| Next Token | 하나를 고름 | 사과 |
| 반복 | 붙이고 다시 계산 | 사과 → 를 → 추천해요 |

- LLM은 입력을 벡터로 준비하고 Transformer Block을 반복해 각 Token의 의미를 문맥에 맞게 업그레이드한 뒤 마지막 자리 벡터로 다음 Token을 하나씩 고른다.

### 가중치는 어떻게 정해지나

- Embedding 표, Q·K·V를 만드는 가중치, FFN의 패턴은 모두 무작위 값에서 시작한다.
- 많은 글에서 앞부분을 보고 다음 Token을 맞히게 한 뒤 틀린 정도(Loss)가 줄어드는 방향으로 모든 가중치를 조금씩 고친다. 이것을 수조 개 Token 분량의 글로 반복한다.
- 대화형 LLM은 그 뒤 질문과 답변 예시, 사람의 평가로 추가 학습한다.

코드 대응(train_gpt2.py)과 직접 해볼 수 있는 실습은 llm-transformer-practice.md에 정리했다.
