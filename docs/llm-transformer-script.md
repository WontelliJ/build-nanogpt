# 발표 대본: LLM 동작 원리

- 나머지는 그대로 읽는 문장
- 예상 시간 약 15분

## 0. 시작

[화면] 요약, 0. 예시 대화

- 이번 과제는 LLM의 구조와 Transformer, 내부 신경망 계층을 공부하는 것이었습니다.
- 결론부터 말씀드리면 LLM은 문장을 숫자 벡터로 바꾸고 Transformer에서 Token끼리 정보를 주고받게 한 뒤 다음 Token 하나를 고르는 과정을 반복합니다.
- LLM은 대규모 언어 모델, Transformer는 2017년에 나온 신경망 구조로 현재 LLM의 기반입니다.
- 설명은 GPT, Claude, Llama 같은 현재 LLM이 공통으로 쓰는 구조를 기준으로 합니다. 코드는 구조가 공개된 GPT-2 구현을 참고했습니다.
- 화면의 대화를 예시로 쓰겠습니다.
- 마지막 질문 그럼 그 사람에게 뭘 사주면 좋을까에는 민수도 사과도 없습니다.
- 그런데 모델은 그 사람이 민수이고 민수가 좋아하는 것이 사과라는 점을 연결해서 사과를 추천합니다.
- 오늘은 이 연결이 어떤 계산으로 만들어지는지를 단계별로 설명하겠습니다.

[화면] 전체 흐름 표

- 각 단계는 직전 단계에서 남은 한계를 해결하기 위해 존재합니다.
- 그래서 단계마다 무엇이 바뀌었고 어떤 한계가 해결됐는지 순서로 보겠습니다.

## 1. Tokenizer

[화면] 1. Tokenizer

- 첫 단계에서는 문장을 Token 단위로 자르고 번호를 붙입니다.
- Token은 모델이 처리하는 텍스트 조각으로 단어 또는 단어의 일부입니다.
- 민수는 사과를 좋아해는 민수, 는, 사과, 를, 좋아해, 마침표, 여섯 개 Token으로 나뉩니다.
- 각 Token에는 사전 번호인 ID가 붙습니다. 민수는 12번, 사과는 31번입니다.
- 대화 전체는 사용자와 AI를 구분하는 특수 Token과 함께 하나의 ID 목록으로 이어져서 입력됩니다.
- 이 단계에서 문자열이 정수 목록으로 바뀌었습니다.
- 남은 한계는 ID에 의미가 없다는 점입니다. 31은 사전에서 사과가 놓인 위치 번호일 뿐입니다.
- 참고로 실제 LLM은 단어 대신 자주 함께 나오는 글자 조합 단위로 자릅니다. 사전 크기는 GPT-2가 약 5만 개, 최근 모델은 10만에서 13만 개 수준입니다.

---

## 2. Embedding

[화면] 2. Embedding, 변환 전

- 두 번째 단계인 Embedding에서는 ID를 벡터로 바꿉니다. 벡터는 숫자 여러 개를 나열한 값입니다.
- 먼저 ID만 있을 때의 문제입니다.
- 사과가 31, 민수가 12, 바나나가 9137이라면 숫자 차이로는 사과가 바나나보다 민수에 더 가깝습니다.
- ID 간 거리는 의미와 관계가 없어서 유사도를 계산할 수 없습니다.

[화면] 변환 후

- Embedding은 ID 번호에 해당하는 행을 표에서 꺼내는 방식입니다.
- 화면은 설명을 위해 3차원으로 줄인 예입니다.
- 두 벡터의 같은 위치 값끼리 곱해서 더하는 것을 내적이라고 합니다.
- 사과와 바나나의 내적은 1.46, 사과와 민수는 0.34입니다. 유사도를 숫자로 계산할 수 있게 됐습니다.
- 각 칸의 의미는 사람이 정하지 않습니다. 학습 중에 비슷하게 쓰이는 Token끼리 가까워지도록 조정됩니다.
- 실제 벡터 크기는 GPT-2가 768, GPT-3가 12,288입니다.

[화면] 남은 한계

- 이 단계에는 한계가 남습니다.
- 첫째, 문맥이 반영되지 않습니다. 배가 고파서 사과를 먹었다의 사과와, 약속에 늦어서 사과를 했다의 사과가 같은 벡터입니다.
- 둘째, 순서가 반영되지 않습니다. 이 Token이 문장의 몇 번째인지 벡터에 없습니다.

## 3. Position

[화면] 3. Position, 반영 전

- 세 번째 단계에서는 Token 벡터에 위치 정보를 더합니다.
- 예시는 사람이 사과를 먹는다와 사과가 사람을 먹는다입니다.
- Transformer는 Token을 하나씩 순서대로 읽지 않고 전체를 한 번에 입력받습니다. 이유는 다음 장에서 설명하겠습니다.
- 위치 정보가 없으면 두 문장은 사람, 사과, 먹는다, 주격 조사, 목적격 조사라는 같은 Token 집합으로 처리됩니다.
- 주격 조사가 사람에 붙었는지 사과에 붙었는지 판단할 수 없어서 두 문장을 구분하지 못합니다.

[화면] 반영 후

- 그래서 위치마다 위치 벡터를 두고 Token 벡터에 더합니다.
- 그러면 0번 위치의 사과와 2번 위치의 사과가 서로 다른 벡터가 됩니다.
- 주격 조사가 바로 앞 Token에 붙는다는 관계를 계산할 수 있게 되어 두 문장이 구분됩니다.
- 남은 한계는 각 Token이 아직 자기 정보만 가지고 있다는 점입니다. 마지막 질문의 사람은 누구를 가리키는지 아직 모릅니다.
- 위치를 넣는 방식은 모델마다 다릅니다. GPT-2와 GPT-3는 위치 벡터를 학습으로 정했습니다. Llama 같은 최근 모델은 RoPE라는 회전 방식을 씁니다.

## 4. RNN에서 Transformer로

[화면] 4. RNN에서 Transformer로

- 이 장은 위치 정보를 왜 Attention 앞에서 따로 넣는지에 대한 설명입니다.
- Transformer는 먼 문맥이 약해지는 RNN의 한계를 Attention으로 해결했고 그 과정에서 사라진 순서 정보를 입력 단계의 위치 정보로 보완했습니다.
- Transformer 이전에는 RNN, 순환 신경망이 주로 쓰였습니다.
- RNN은 Token을 앞에서부터 하나씩 처리하면서 이전 내용을 고정된 크기의 상태값 하나에 누적해 넘깁니다.
- 순서는 처리 순서로 자연스럽게 반영됩니다.
- 하지만 입력이 길수록 앞부분 정보가 약해집니다. 예시에서 사주면까지 처리할 때는 첫 문장의 민수와 사과 정보가 약해진 상태입니다.
- 또 앞 Token이 끝나야 다음 Token을 처리할 수 있어서 병렬 계산이 어렵습니다. 그만큼 모델을 크게 만들기도 어렵습니다.
- 2017년 Attention Is All You Need 논문은 RNN을 없앴습니다.
- 대신 각 Token이 다른 모든 Token을 직접 참조하고 얼마나 참조할지를 가중치로 계산합니다. 이것이 Attention입니다.
- 세 문장 앞의 사과도 바로 앞 Token과 같은 한 단계로 참조하기 때문에 거리로 인한 정보 손실이 없습니다.
- 모든 Token을 동시에 계산하므로 병렬 처리도 가능합니다.
- 대신 순서 정보가 사라지기 때문에 입력 단계에서 위치 정보를 먼저 더하게 됐습니다.

[화면] 이후 변화, 연표

- 병렬 계산이 가능해지면서 모델과 학습 데이터를 크게 늘릴 수 있게 됐습니다.
- 2020년에는 규모가 커질수록 성능이 일정하게 좋아진다는 Scaling Law 연구가 나왔습니다.
- GPT-1이 1억 파라미터, GPT-2가 15억, GPT-3가 1,750억으로 커졌습니다. 2022년 ChatGPT 이후 현재의 LLM으로 이어졌습니다. 파라미터는 학습으로 정해지는 모델 내부 숫자입니다.
- 기본 구조는 GPT-1부터 지금까지 같습니다. 바뀐 것은 주로 규모와 세부 구성 요소입니다.

## 5. Self-Attention

[화면] 5. Q, K, V 정의

- 다섯 번째 단계는 Token끼리 정보를 주고받는 Self-Attention입니다.
- 각 Token이 차례로 Query가 되어 다른 Token들의 Key와 비교하고 관련도 비율만큼 Value를 가져와 자기 벡터에 더합니다.
- Query는 현재 Token이 찾는 정보입니다.
- Key는 각 Token이 가진 정보의 특징으로 Query와 비교하는 데 씁니다.
- Value는 선택됐을 때 실제로 전달되는 정보입니다.
- 세 값은 같은 Token 벡터에 서로 다른 가중치 행렬을 곱해서 만듭니다. 이 행렬도 학습으로 정해집니다.

[화면] 계산 순서

- 먼저 한 Token이 Query가 됩니다.
- Query와 각 Token의 Key를 내적해서 관련도 점수를 냅니다.
- Softmax로 점수를 합이 1인 비율로 바꿉니다.
- 비율만큼 각 Token의 Value를 가져와 합한 뒤 현재 Token 벡터에 더합니다.
- 이것을 모든 Token이 돌아가며 수행합니다. 실제로는 행렬 연산으로 동시에 계산합니다.
- 참조 범위는 자기 자신과 앞쪽 Token까지입니다. 이를 Causal Attention이라고 합니다.
- 학습할 때 다음 Token이 정답이기 때문에 뒤쪽을 보면 정답을 미리 보는 것과 같아서 가립니다.

[화면] 예시 1

- 사람이 Query인 경우입니다. 찾는 정보는 가리키는 대상이 누구인가입니다.
- 민수, 그, 과일 가게, 사과의 Key와 비교하면 민수가 70%로 가장 높습니다.
- 그래서 사람 벡터에 민수의 Value가 70% 반영됩니다.
- 적용 전의 사람은 대상이 정해지지 않은 일반 명사였습니다. 적용 후에는 민수 정보가 반영된 벡터가 됩니다.
- 이렇게 그 사람 = 민수가 연결됩니다.

[화면] 예시 2

- 사주면이 Query인 경우입니다. 찾는 정보는 무엇을 사 줘야 하는가입니다.
- 사과가 55%, 좋아해가 20%로 반영됩니다.
- 적용 후 사주면 벡터에는 사과와 좋아함 정보가 들어갑니다.

[화면] 2장 한계 해결

- 2장에서 남은 문맥 문제도 여기서 해결됩니다.
- 배가 고파서 사과를에서는 사과가 배가 고파서의 Value를 가져와 과일 의미가 됩니다. 약속에 늦어서 사과를에서는 사죄 의미가 됩니다.
- 비율을 정하는 기준은 거리가 아니라 Query와 Key의 관련도입니다. 그래서 세 문장 앞의 민수와 사과도 높게 반영될 수 있습니다.

## 6. Multi-Head Attention

[화면] 6. Multi-Head

- 여섯 번째 단계는 Attention을 여러 개로 나눠 동시에 수행하는 Multi-Head Attention입니다.
- Head가 하나면 비율 분포도 하나뿐입니다.
- 사주면이 대상인 민수와, 민수가 좋아하는 사과를 동시에 참조하려면 하나의 비율을 나눠 써야 합니다. 그래서 둘 다 약하게 반영됩니다.
- Head를 여러 개 두면 각 Head가 독립적으로 Query, Key, Value를 계산합니다.
- 한 Head는 대상, 다른 Head는 원하는 것, 또 다른 Head는 문장 구조를 참조하는 식으로 여러 관계를 동시에 가져온 뒤 결과를 이어 붙입니다.
- 각 Head가 어떤 관계를 볼지는 학습으로 정해집니다.
- Head 수는 GPT-2가 12개, GPT-3가 96개입니다.
- 최근 모델은 여러 Query Head가 Key와 Value를 공유하는 GQA 방식을 써서 생성 속도와 메모리 사용량을 줄입니다.

## 7. FFN

[화면] 7. FFN

- 일곱 번째 단계는 FFN, 피드포워드 신경망입니다.
- Attention이 다른 Token에서 정보를 가져오는 단계라면 FFN은 각 Token이 가져온 정보를 개별적으로 변환하는 단계입니다. FFN에서는 다른 Token을 참조하지 않습니다.
- Attention 이후 사주면 벡터에는 민수, 사과, 좋아함, 과일 가게 정보가 섞여 있습니다. FFN은 이것을 다음 Layer에서 쓰기 좋은 형태로 변환합니다.
- 구조는 차원을 넓혔다가 활성화 함수를 거쳐 다시 줄이는 형태입니다. 활성화 함수는 비선형 변환을 가능하게 하는 함수입니다.
- GPT-2는 768에서 3072로 넓혔다가 다시 768로 줄입니다. Llama 같은 최근 모델은 SwiGLU라는 변형을 씁니다.
- FFN은 Block 파라미터의 절반 이상을 차지합니다. 학습한 사실과 패턴의 상당 부분이 여기에 저장된다는 분석 연구가 있습니다.
- 일부 최신 모델은 FFN을 여러 개 두고 Token마다 일부만 계산하는 MoE 구조를 씁니다.

---

## 8. Residual Connection, LayerNorm

[화면] 8. Residual, LayerNorm

- 여덟 번째 단계는 Layer를 깊게 쌓기 위한 구조인 Residual Connection과 LayerNorm입니다.
- Residual Connection은 입력을 출력에 그대로 더하는 연결입니다.
- 적용하지 않으면 각 단계가 벡터를 새로 만들기 때문에 Layer를 거칠수록 Token의 원래 정보가 사라지고 학습 신호도 앞쪽 Layer까지 잘 전달되지 않습니다.
- 적용하면 기존 벡터는 유지하고 각 단계의 결과만 더하므로 원래 정보가 보존되고 수십 개 이상의 Layer도 학습할 수 있습니다.
- LayerNorm은 벡터 값의 평균과 크기를 일정 범위로 맞추는 연산입니다. Layer를 거치며 값이 지나치게 커지거나 작아지는 것을 막습니다.
- 최근 모델은 계산이 더 단순한 RMSNorm을 주로 씁니다.
- 정규화, Attention, 더하기, 정규화, FFN, 더하기까지가 Transformer Block 하나입니다.

## 9. Layer 반복

[화면] 9. Layer 반복

- 아홉 번째 단계에서는 Block을 여러 층 반복합니다. GPT-2는 12층, GPT-3는 96층, Llama 3 70B는 80층입니다.
- Block이 하나면 직접 연결된 정보만 한 번 가져옵니다. 마지막 위치가 사람을 참조해도, 그 시점의 사람에는 아직 민수 정보가 없을 수 있습니다.
- 여러 층을 쌓으면 1층에서 사람이 민수 정보를 가져옵니다. 2층에서는 사주면이 민수 정보가 들어간 사람과 사과를 가져옵니다. 이후 층에서는 마지막 위치가 그 결과를 다시 가져옵니다.
- 이렇게 Value가 층마다 전달되고 누적되면서 사과, 민수, 그 사람, 마지막 위치로 이어지는 연결이 만들어집니다.
- 층별 역할은 설명용으로 나눈 것입니다. 실제로는 여러 Head와 Layer에 나뉘어 있습니다.
- Token 자체가 바뀌는 것이 아니라 같은 위치의 벡터가 층마다 갱신됩니다. 마지막 층의 벡터를 Hidden State라고 합니다.

## 10. 출력

[화면] 10. 출력

- 열 번째 단계에서는 다음 Token을 고릅니다.
- 마지막 위치의 Hidden State 하나만 사용합니다. Causal Attention으로 앞쪽 모든 정보가 이미 여기에 반영되어 있기 때문입니다.
- 이 벡터를 사전의 모든 Token에 대한 점수로 바꿉니다. 이 점수를 Logits라고 합니다.
- 사과 8.4, 바나나 5.1처럼 나오고 Softmax로 확률로 바꾸면 사과가 약 95%입니다.
- 가장 높은 Token을 고를 수도 있고 확률에 따라 무작위로 뽑을 수도 있습니다. 같은 질문에 답이 달라지는 것은 이 무작위 선택 때문입니다. 그 정도는 Temperature 값으로 조정합니다.

## 11. 생성 반복

[화면] 11. 생성 반복

- 열한 번째 단계는 생성 반복입니다. LLM은 Token을 한 번에 하나씩만 만듭니다.
- 마지막 질문 다음에 사과가 선택되면 사과를 문맥 뒤에 붙이고 다음 Token을 다시 계산합니다.
- 그러면 를이 나옵니다. 다시 붙여서 계산하면 추천해요가 나옵니다.
- 종료 Token이 나오거나 최대 길이에 도달하면 멈춥니다.
- 실제 LLM은 앞쪽 Token의 Key와 Value를 저장해 두는 KV Cache를 써서 매번 전체를 다시 계산하지 않고 새 Token만 계산합니다.
- 한 번에 볼 수 있는 길이인 Context Window는 GPT-2가 1,024 Token, 최근 모델은 12만 8천 Token 이상입니다.

## 12. 학습

[화면] 12. 학습

- 마지막으로, 지금까지 나온 모든 가중치는 무작위 값에서 시작합니다.
- 사전학습에서는 민수는 사과를 다음에 올 Token을 예측하게 합니다. 정답 좋아해와의 차이인 Loss를 계산한 뒤 역전파로 정답 확률이 높아지는 방향으로 가중치를 수정합니다.
- 이것을 수조 개 Token 규모의 텍스트로 반복합니다.
- 다음 Token을 맞히는 과정에서 문법, 지시 대상, 사실 관계 같은 패턴이 가중치에 반영됩니다.
- 사전학습만 한 모델은 문장을 이어 쓰기만 합니다.
- 질문에 답하는 대화형 모델이 되려면 질문과 답변 예시로 추가 학습하는 SFT, 사람이 더 낫다고 평가한 답변 쪽으로 학습하는 RLHF를 거칩니다.
- ChatGPT와 Claude 같은 서비스는 이 두 과정을 거친 모델입니다.

## 13. 정리

[화면] 13. 정리 표

- 정리하겠습니다.
- 문장은 Token ID가 되고 ID는 유사도를 계산할 수 있는 벡터가 됩니다. 여기에 위치 정보가 더해집니다.
- 각 Token은 Query로 필요한 정보를 찾고 Key로 대상을 비교한 뒤 Value를 가져와 자기 벡터에 누적합니다.
- 이 과정을 여러 Head와 여러 Layer에서 반복하면서 그 사람 = 민수, 민수가 좋아하는 것 = 사과라는 정보가 마지막 위치까지 전달됩니다.
- 마지막 위치 벡터로 다음 Token 점수를 계산하면 사과가 가장 높게 나옵니다.
- Transformer는 Token 간 정보 교환을 여러 층 반복하는 구조입니다. LLM은 그 결과로 다음 Token을 하나씩 선택하는 과정을 반복합니다.
